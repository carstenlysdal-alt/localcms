# ADR-013 – AI-operatør, værktøjsregister og chat-UI

Dato: 2. oktober 2026. Status: **Foreslået** (afventer ejerens godkendelse, Fase 0-gate). Hører til `docs/localrating/README.md`.

## Kontekst
CMS'et får en **AI-operatør** (tale/skrift → værktøjer): `lib/operator/{types,policy,prompt,confirm,events,sanitize,audit}.ts`, `tools/{sections,areas,shared}.ts`, permission `OPERATOR_USE`, tabel `OperatorAction` – **under opbygning af en anden agent på auditdagen** (ingen route/UI/register-index endnu). Kontrakten findes: `defineTool` med risiko `read | safe-write | confirm`, `permissions`/`alsoRequires`, `BLOCKED_TOOLS`, engangs-bekræftelse (`confirm`), fortryd-recepter, NDJSON-events, `OPERATOR_PROMPT` med SYSTEM/BRUGER/HENTET-adskillelse. Ejeren: operatøren skal kunne **oprette alt** (sektioner, artikler/kladder, feeds, kilder, kandidater, rating-/genereringskørsler, udgivelsesplaner, simulatorscenarier, prompt-versioner m.m.) via værktøjsregistret; LocalRating-værktøjer registreres **fase for fase**; chat-/operator-UI skal følge skillet `chat-module`.

## Beslutning
1. **LocalRating leverer værktøjer, ikke en egen operatør.** Værktøjer ligger i `lib/operator/tools/localrating/**` og registreres med ét import-led pr. fase i operatørens register; operatørens egne filer røres ikke (D28 afklarer ejerskab af registret).
2. **Værktøjsliste og risikoniveau pr. værktøj:** `04-…` §5.1 (read / safe-write / confirm). **AI-forbrug = `confirm`** med pris i bekræftelseskortet. Oprettelse af feeds/kandidater/workspaces/scenarier/planer/prompt-udkast = `safe-write` med fortryd; aktivering (prompt, ratingprofil, feed), rights-ændring, hand-over til kladde, anvend-som-forslag = `confirm`.
3. **Blokeret for operatøren** (tilføjes til `BLOCKED_TOOLS`): ændring af forbrugsloft, udbyder-/`allowedProviders`-/DeepSeek-indstillinger, nøgler, `production.*`-rettigheder; plus allerede blokeret: publicering, forside-godkendelse/-publicering. Operatøren kan aldrig mere end brugerens egne rettigheder.
4. **Værktøjer kalder servicelaget** (rettigheder/instans/budget tjekkes dér), returnerer kun **rights-gated** data (aldrig `rawPayload`/tipindhold) og er **HENTET INDHOLD** for modellen.
5. **Chat-UI** (operatør, Local Arbejdsrum, playground, simulator-dialog) bygges på delte komponenter i `components/chat/**` efter `chat-module`: streaming-sikker markdown, auto-scroll kun nær bund (ingen `smooth`), typing-indikator m. reduced motion, input (Enter/Shift+Enter, auto-grow, disabled under stream), kopi-knap, fejl/retry; plus bekræftelseskort og fortryd for operatør-events. Ny afhængighed til markdown (D23). Eksisterende `/redaktion/chat` bryder flere punkter (audit i `04-…` §6); migration er beslutning D24.
6. `OPERATOR_PROMPT` registreres (kode, skrivebeskyttet) i prompt-biblioteket (ADR-009).

## Konsekvenser
+ Operatøren kan gøre alt LocalRating kan – med de samme sikkerhedsgarantier som resten af CMS'et.
+ Én UI-standard for alle chat-flader.
− Koordinering med operatør-sporet (registret, tests, prompt); kode i bevægelse (R27).
− Rights-gate og pris-bekræftelser gør værktøjerne mere omstændelige (bevidst).

## Alternativer (fravalgt)
- Egen LocalRating-operatør: dobbelt rettigheds-/audit-logik; afvist.
- Operatøren må aktivere prompter/udbydere uden klik: injektionsrisiko; afvist.
- Egen chat-UI pr. flade: inkonsistens; afvist.
