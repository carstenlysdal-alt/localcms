# ADR-016: Kilder hentes kun manuelt (knap) indtil ejeren slår automatik til

**Status:** Besluttet af ejeren (3. okt. 2026). **Gælder:** alle LocalRating-kilder (SourceDefinition) for alle instanser.

## Kontekst
Registrene for Næstved og Slagelse rummer ~167 kilder med P0/P1/P2-prioriteter, der som udgangspunkt kunne pollles automatisk (1–5 min / 15–60 min / 1–12 t). Ejeren vil først se, hvordan flowet virker, og vil ikke have, at noget kører af sig selv endnu (AI-forbrug, rettigheder, støj, driftsrisiko).

## Beslutning
1. **Ingen automatisk indhentning.** Der oprettes ikke noget Railway-cron til LocalRating-ingest i denne fase. Cron-endpointet (`/api/cron/localrating`) bygges, men er **slået fra som standard**: global feature-flag (`LOCALRATING_AUTOPOLL=0`, default 0) OG pr. instans (`LocalRatingConfig.autoPollEnabled=false`, default false). Begge skal være sande, før noget kører automatisk. Endpointet svarer `409 autopoll slået fra` ellers.
2. **Alt udløses med en knap** (server action/route med rettighed `production.manage`):
   - "Hent nu" pr. kilde (kildetabellen og kandidatsiden),
   - "Hent alle aktive" pr. instans (valgfrit filter: prioritet P0/P1/P2, kildeklasse, by),
   - "Test feed/kilde" (tørkørsel uden at gemme),
   - "Opdag nye kilder" (discovery-jobbet) som egen knap.
   Rating og artikelgenerering er også kun knap-udløste (kandidatside: "Rate", "Skriv med AI"); der er ingen automatisk rating/generering.
3. **Kun aktive kilder hentes.** Importerede kilder er `enabled=false`/`approvalStatus=foreslået`; en redaktør skal aktivere dem (kræver URL + bestået test, jf. ADR-015). "Hent alle" rører kun aktive, godkendte kilder.
4. **Beskyttelse mod misbrug og uheld:** per-kilde cooldown (standard 60 s, konfigurerbar), global samtidighedsgrænse (maks. 3 samtidige hentninger pr. instans), `rateLimit` pr. bruger, SSRF-regelsættet og `rightsLevel` gælder uændret, hentning sker i små batches via `ProductionJob`, og UI'et viser fremdrift (polling) i stedet for at holde én lang request åben (Railway-timeout). Alle knaptryk auditeres (`AuditLog`: hvem, hvilke kilder, antal items; aldrig indhold).
5. **AI-forbrug følger kun knap-handlinger** og stadig forbrugsloftet (D5). `AI spærret indtil loft sat` bevares.
6. **Senere aktivering af automatik** sker i trin: (a) ejeren sætter flagget, (b) opretter Railway-cron med `Bearer CRON_SECRET`, (c) vælger prioriteter pr. instans (fx kun P0 først). Det kræver ingen kodeændring ud over konfiguration.
7. **AI-operatøren** får værktøjerne `fetch_source_now` og `fetch_all_sources` med risikoniveau `confirm` (de koster tid/ressourcer og kan ramme eksterne systemer), så "hent kilderne" kan siges højt, men først efter bekræftelse.

## Konsekvenser
- Ingen baggrundstrafik, ingen overraskelser i omkostning eller kildernes logfiler; ejeren ser og styrer hvert trin.
- P0-"breaking"-hastigheden fra registrene (1–5 min) opnås først, når automatik slås til.
- Cron-dele i dokumenterne (10 §11f, 12 Fase 2) læses som "funktionalitet bygges, men er slået fra".

## Alternativer
Automatisk polling fra start (afvist af ejeren), automatik kun for P0 (kan vælges senere via trin 6c).
