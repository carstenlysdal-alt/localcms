# ADR-017: AI-operatørens modeludbyder (DeepSeek eller Anthropic) og dataminimering

**Status:** Besluttet af ejeren (3. okt. 2026). **Gælder:** AI-operatøren (`/api/operator`, `lib/operator/**`). **Ændrer delvist:** ADR-007 (DeepSeek er ikke længere spærret for operatøren).

## Kontekst
ADR-007 spærrer DeepSeek som standard, fordi udbyderen behandler data uden for EU/EØS. Ejeren har eksplicit valgt DeepSeek til AI-operatøren (pris/ydelse) og vil sætte nøglen som Railway-variabel. Operatøren kan læse indbakke, brugerliste og artikler og kalde værktøjer, så den kommer i berøring med persondata, hvis intet gøres.

## Beslutning
1. **Udbyderabstraktion for operatøren** (`lib/operator/llm/`): neutralt beskedformat + `stream/complete`; adaptere `anthropic` (uændret adfærd) og `deepseek` (OpenAI-kompatibel Chat Completions med function calling, kun `fetch`, ingen ny afhængighed).
2. **Valg:** `OPERATOR_PROVIDER=deepseek|anthropic`; ellers DeepSeek hvis `DEEPSEEK_API_KEY` er sat, ellers Anthropic hvis `ANTHROPIC_API_KEY` er sat, ellers 503 (dansk besked der nævner begge variabler). Et eksplicit valg uden nøgle falder **ikke** stille tilbage til den anden udbyder (samme princip som ADR-007 pkt. 4: data flyttes ikke i det skjulte).
3. **Nøgler kun som Railway-variabler** (`DEEPSEEK_API_KEY`, valgfrit `DEEPSEEK_MODEL`, `DEEPSEEK_BASE_URL`, `OPERATOR_PROVIDER`). Ingen nøgler i databasen, ingen BYOK. Ejeren sætter nøglen fra egen terminal (`railway variable set DEEPSEEK_API_KEY --stdin`), så værdien aldrig står i chat eller historik.
4. **GDPR-afbødning for DeepSeek (dataminimering, `lib/operator/redact.ts`):**
   - e-mail og telefon i samtale og værktøjsresultater erstattes af stabile pladsholdere (`[e-mail-k…]`); pladsholdere gendannes kun **lokalt** i værktøjsargumenter og svartekst til redaktøren, så "opret bruger anna@…" stadig virker uden at adressen forlader processen;
   - CPR-lignende numre, danske kontonumre og nøgler fjernes helt;
   - kontaktfelter (e-mail, telefon, afsender, adresse, kontakt, ip, adgangskode, token …) fjernes fra al værktøjsdata; hvert værktøj erklærer desuden egne felter (`ToolDef.externalLlm`): navn på brugere og indsendere, uddrag af indsendelser, forfatter, ophavsperson;
   - brugerens eget navn sendes ikke (kontekst: "redaktøren"); en sidste, tilstandsløs maske i adapteren dækker alt udgående;
   - kun operatøren er omfattet; tips/Q&A/indbakke/brugere returneres kun som id, titel, status og antal.
5. **Revisionsspor:** hver udført handling og hver tur med ekstern udbyder logger udbydernavn, promptversion og tal for maskeret/fjernet (aldrig indhold). Promptversionen er uændret (`operator-v1.0`); data-blokkene (`<hentet_indhold>`) og tool-skemaerne (zod-registret) er identiske for begge udbydere.
6. **Circuit breaker pr. udbyder:** `operator:deepseek`; Anthropic bruger fortsat den delte `anthropic`.

## Hvad bliver på Anthropic (på beslutningstidspunktet)
Editorens felt-AI, forsidens ranker og `/api/chat` bruger fortsat `lib/frontpage/ai-client.ts` / `ANTHROPIC_API_KEY`. De kan flyttes til DeepSeek (eller en anden udbyder) via den planlagte fælles AI-gateway (`lib/ai/`, `09-ai-gateway-og-noegler.md`); `redact.ts` og SSE-/adapterdelene i `llm/deepseek.ts` er skrevet, så gatewayen kan genbruge dem. Skiftet kræver en ny, separat vurdering pr. flade (de sender artikeltekst og kan indeholde persondata).

## Konsekvenser
+ Operatøren virker med DeepSeek uden at persondata (e-mail, telefon, CPR, kontaktfelter, navne i felter) forlader processen; udbyderen kan skiftes med én variabel.
− **Rest-risiko:** navne og andre personoplysninger i fri tekst (redaktørens egne beskeder, artikelbrødtekst, titler på indsendelser) kan ikke genkendes mekanisk og sendes. UI viser en note, og redaktøren bør undgå persondata i beskeder.
− DeepSeeks tool-calling er ikke Claudes: mere ugyldig JSON og flere ekstra kald forventes (håndteres: ugyldige argumenter afvises og modellen prøver igen; loft på 8 kald).
− Ejeren skal selv vurdere databehandleraftale og overførselsgrundlag (dette er ikke juridisk rådgivning) og verificere DeepSeeks aktuelle vilkår, modelnavne og priser (ikke verificeret her).

## Alternativer (fravalgt)
Maskering af navne via NER (upålideligt/dyrt); DeepSeek kun uden værktøjsdata (operatøren ville blive ubrugelig); stille fallback mellem udbydere (afvist, jf. ADR-007).
